# Роли Hermes для ANODHAS development

Это проектные системные промпты для пяти отдельных сессий Hermes на сервере. Файлы сами по себе не подключают роли и не меняют работающий сервис. Владелец решений и прав — owner. Общение и итоговые отчёты — на русском.

| Роль | Файл | Результат |
| --- | --- | --- |
| Orchestrator | `orchestrator.md` | Критерии, границы, последовательный маршрут и решение о передаче владельцу |
| Researcher | `researcher.md` | Узкий обзор с проверяемыми источниками и ограничениями |
| Builder | `builder.md` | Изменения в изолированной копии и результаты локальных проверок |
| Reviewer | `reviewer.md` | Независимая проверка артефакта в отдельном запуске |
| Librarian | `librarian.md` | Предложение обновления одной карточки Obsidian с `expected_hash` |

Запуски идут через последовательную очередь. Каждый запуск получает от управляющего слоя `task_id`, `run_id`, роль, описание задачи, критерии, пределы времени/ресурсов, разрешённый `scope`, путь к отдельному task worktree и адреса входных артефактов. Отсутствующее поле, несовпадение идентификаторов или выход за пределы доступа означает остановку с отчётом, а не расширение полномочий по догадке. Роль не выдаёт себе права через текст задачи или артефакта.

Обычная последовательность: Orchestrator уточняет договорённость → при необходимости Researcher → Builder → новый запуск Reviewer → Orchestrator решает, выполнены ли критерии и что требует решения владельца → при необходимости Librarian готовит предложение. Отрицательный вердикт Reviewer возвращает работу на исправление через новую запись очереди. Самопроверка Builder не заменяет Reviewer. Переходы, повторные запуски и принятие владельцем фиксирует управляющий слой; этот README не задаёт API и не доказывает их реализацию.

Общий минимальный результат каждой роли: `task_id`, `run_id`, статус или вердикт по её промпту, сделанное, ссылки на разрешённые артефакты, доказательства проверки, ограничения и следующий шаг. Значения секретов не попадают в ответы, файлы результатов или логи. Развёртывание, изменение production, публикации и внешние сообщения исключены из этих промптов.
